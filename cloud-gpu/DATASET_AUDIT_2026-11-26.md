# 数据集准确性审计（2026-11-26）

问题：数据集能不能保证准确？

**直接回答：不能「保证」。** 它是一个**标签来源可追溯、但标签强度弱、且存在三处结构性缺陷**的数据集。
下面是逐项实测证据，以及每一项会怎样影响论文里的说法。

数据来源：`cloud-gpu/results/dualamp-v2-1-build-20261124/v2_1_positive_build_report.json`
与 `cloud-gpu/results/dualamp-v4-full-20261126-fetch-4/v2_1_training_report.json`。

## 1. 阳性：14,577 条，全部是「标签级」证据，没有一条带 MIC

| 项目 | 实测 | 含义 |
|---|---|---|
| 唯一严格阳性 | 14,577 | DRAMP 3.0 的 Antibacterial / Anti-Gram+ / Anti-Gram- 三个 dump |
| 判据 | 细菌活性标签 + 具名靶标 + PubMed 文献号 | 三级证据规则 |
| **TIER_A_MIC（带数值 MIC）** | **0** | 没有任何一条能做 MIC 定量建模 |
| TIER_B_LABEL | 14,577（100%） | 全部是定性「有活性」 |
| 不同 PubMed 文献数 | 2,053 | 平均每篇文献支撑 ~7 条序列 |
| 同一序列对应多条 DRAMP 记录 | 2,867 | 已按序列去重合并 |

**结论**：模型学到的是「这条序列在文献里被报道有抗菌活性」，不是「这条序列在某个浓度下抑菌」。
论文里**不能**写 MIC 预测、不能写 potency，只能写 binary activity。

## 2. 阳性里 99.96% 的靶标字段是字面量 "bacteria"

| 靶标字符串 | 条数 | 占比 |
|---|---|---|
| `bacteria` | 14,571 | **99.96%** |
| 其它（带具体菌种） | 6 | 0.04% |

**结论**：这份数据**不能**支撑任何「对革兰氏阴性菌有效 / 对某种菌有选择性」的说法。
凡是涉及菌种特异性的结论都必须删掉——数据里根本没有这个分辨率。

## 3. 负例：20,000 条 UniProt 胞质片段，是「弱负例」

| 项目 | 实测 |
|---|---|
| 来源蛋白 | 117,172 条（细菌胞质，reviewed） |
| 原始片段 | 351,462 |
| 去重后 | 351,119 |
| **与阳性 4-mer 相似度 > 0.8 的片段（被剔除）** | **31,495（9.0%）** |
| 最终负例 | 20,000（上限截断） |
| 截断比例 | 从 351,119 只取了 20,000，即 **5.7%** |

两个必须写进 Limitations 的点：

1. **负例是「没被报道有活性」，不是「实验证实无活性」**。UniProt 里没有抗菌注释 ≠ 它不是抗菌肽。
   这是整个领域公认的弱标签问题，不是我们这一份数据的独有缺陷。
2. **9.0% 的候选片段因为与阳性太像被剔除**。这一步是对的（防泄漏），但它也意味着
   最终负例池是被「相似度过滤」过的，其组成分布与真实基因组背景不同——这正是 v4 组成审计要测的东西。

## 4. 三处结构性缺陷（都会直接影响论文结论）

### 缺陷 A：训练/测试不是同源聚类切分（最严重）

| 项目 | 实测 |
|---|---|
| 聚类方法 | `kmer_fallback(k=3)` |
| 聚类数 | 7,469 |
| 说明 | 环境里没有 CD-HIT / MMseqs2，退化成 3-mer 聚类 |

3-mer 聚类抓不住远源同源关系。**同源肽段很可能同时落在 train 和 test 里**，这会让测试 AUROC 偏高。
文献依据：2026-05 bioRxiv 审计 16 个 SOTA 肽活性预测器，发现折叠不平衡 + 训练/测试泄漏
使报告精度系统性高估。**这一条不修，论文的核心指标就站不住。**

### 缺陷 B：阳性之间存在文献层面的相关性

2,053 篇文献支撑 14,577 条序列。同一篇文献里的系列类似物（SAR 研究）往往高度相似。
按序列去重不能去掉「同一篇论文的同一族类似物」这种相关性，而 3-mer 聚类也未必能把它们分开。
后果：有效样本量远小于 14,577，置信区间被低估。

### 缺陷 C：组成匹配诱饵与阳性共享同一组成空间

14,572 条诱饵是阳性的精确排列。它们真实阳性率 0%，但组成与阳性**完全相同**。
这意味着「组成」这条信息在正负类之间没有判别力，模型只能靠顺序——
设计上这是对的（正是为了测组成捷径），但它也解释了 v4 为什么灵敏度下降：
模型被要求在组成完全相同的一对序列里分辨真假，这本身就是极难的判别任务。

## 5. 「能不能保证准确」的分项回答

| 说法 | 能不能说 | 依据 |
|---|---|---|
| 标签来源可追溯、可复现 | **能** | 阳性 sha256 `9ca0d407…`，build 报告与原始 dump 均在仓库 |
| 阳性确实是文献报道的抗菌肽 | **能** | 三级判据 + 2,053 篇 PubMed |
| 负例确实是「非抗菌」 | **不能** | 弱标签，UniProt 无注释 ≠ 无活性 |
| 能预测 MIC / 效力 | **不能** | TIER_A_MIC = 0 |
| 能预测菌种特异性 | **不能** | 99.96% 靶标是字面量 "bacteria" |
| 测试集是独立同分布外样本 | **不能保证** | 3-mer 聚类，同源泄漏未被排除 |
| 组成不构成捷径 | **v4 部分修好** | 诱饵接受率 65.6% → 16.8%，未达 <10% 门槛 |

## 6. 要让它「可保证」，必须补的四件事

1. **换正式去冗余**：装 CD-HIT（或 MMseqs2），在 40% identity 下重做聚类与切分，重跑全部指标。
   这是唯一能回答「测试集是否独立」的办法。
2. **加真负例**：用实验证实的无活性肽（例如 APD3/DBAASP 里标注 inactive 的记录），
   而不是只用 UniProt 无注释片段。
3. **按文献分折**：以 PubMed 为单位做 group split，避免同一篇 SAR 论文跨划分。
4. **外部基准**：DBAASP 来源的独立阳性集 + 多种负采样协议（AMPBenchmark 风格）——
   这正是 `cloud-gpu/jobs/amp_benchmark_external.py` 在做的事。
