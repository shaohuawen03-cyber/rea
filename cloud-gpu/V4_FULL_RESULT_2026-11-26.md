# DualAMP v4 全量训练结果（2026-11-26）

运行：`shaohuawen/dualamp-v4-full-20261126`（GPU T4，5 seeds / 60 epochs / 5 folds）
报告：`cloud-gpu/results/dualamp-v4-full-20261126-fetch-4/v2_1_training_report.json`

## 1. 结论（一句话）

v4 把「组成捷径」压下去了，但**没有压到门槛内**，代价是**固定特异度下灵敏度接近腰斩**。
因此 v4 **不是**「高分 SCI 支持的硕士论文发表版模型」，只能作为**探索性（Pre-release）**发布，
并附完整失败证据。

## 2. 组成匹配诱饵接受率（真实阳性率 0%）

| 模型 | v2.1 | v4 冒烟(1000 负例) | v4 全量(6000 负例) | 门槛 <10% |
|---|---|---|---|---|
| M1（均值池化） | 70.24% | 63.67% | 46.17% | 未通过 |
| M2（CNN） | 67.53% | 6.17% | 17.13% | 未通过 |
| M3（主模型） | 65.64% | 5.67% | 16.78% | 未通过 |

不同尺度下不一致（冒烟 6% → 全量 17%）说明这不是单调收敛的修复，而是与负例预算/训练步数耦合。

## 3. 代价：固定特异度下的灵敏度（阈值取自 dev OOF，不看测试集）

| 模型 @ 目标特异度 | v2.1 | v4 | 变化 |
|---|---|---|---|
| M1 @ 0.990 | 86.08% | 48.45% | −37.6 pt |
| M1 @ 0.995 | 79.26% | 38.14% | −41.1 pt |
| M2 @ 0.990 | 87.22% | 49.48% | −37.7 pt |
| M2 @ 0.995 | 82.67% | 38.14% | −44.5 pt |
| M3 @ 0.990 | 81.53% | 45.36% | −36.2 pt |
| M3 @ 0.995 | 75.00% | 42.27% | −32.7 pt |

AUROC 只从 0.989 掉到 0.950，**AUROC 完全掩盖了这个代价**。

## 4. 组成-only 对照（泄漏规避协议）

- 20 维氨基酸频率 + 逻辑回归：train 拟合 → val 定阈值 → test 打分
- 对照 AUROC = **0.8073**；最强深度模型 M2 = **0.9513**
- 组成可解释占比 = **84.9%**
- 配对 bootstrap ΔAUROC = **+0.1430 [0.0939, 0.1981]，p < 0.001**（1000 次有效重采样）

深度模型确实显著优于纯组成基线；但「84.9% 的 AUROC 由组成解释」这个数字本身说明
判别力的大部分仍来自组成分布，而不是基序。

## 5. 泄漏审计（必须写进 Limitations）

| 项目 | 数值 |
|---|---|
| 诱饵池总数 | 14,572 |
| 可训练硬负例 | 6,000 |
| held-out 挑战集 | 8,572（实际挑战评估 9,071 条：leanrea 另加了自己的 scrambled 副本） |
| 两侧重叠 | 0 |
| 可训练硬负例 = 某个 held-out 阳性的排列 | **5,815 / 6,000 = 96.9%** |

最后一项是本次设计最大的结构性缺陷：因为「一条诱饵 = 某个阳性的排列」，池子对半切之后，
可训练诱饵几乎必然覆盖 held-out 阳性的组成。方向上它是保守的（只会压低这些阳性的得分），
不会抬高 AUROC，但它解释了一部分灵敏度损失，也说明这种「排列式诱饵」不能同时充当
训练负例与评估集合。**v5 必须换设计**（见 `cloud-gpu/jobs/dualamp_v5_train.py`）。
