q['jobs'].append({"id":"dualamp-v2-1-full-rN-20261125","provider":"kaggle","mode":"run",

然后加 `mode: status` 和 `mode: output` 两条轮询任务；`output` 会把
`v2_1_training_report.json` / `v2_1_training.log` 拉进 `cloud-gpu/results/<job_id>/`。

## 3. 出发布包

```bash
python3 cloud-gpu/jobs/dualamp_v2_1_publish.py dualamp-v2-1-full-rN-20261125
# → cloud-gpu/results/dualamp-v2-1-publish-<UTC date>/
```

档位判定（`decide_tier`）：
- `V2_1_VALIDATED` —— 所有 blocker 为空（目前不可能，组成挑战会挂）。
- `V2_1_EXPLORATORY` —— 训练完成 + 有指标，但有 blocker。
- `NOT_RELEASABLE` —— 训练未完成。

发布器不会替你把 blocker 说成通过。**要发正式版，先让组成挑战 PASS。**

## 4. 私有权重包（当前无留存副本）

**现状**：r3 生成的 759,753,038 B 包已随容器销毁，任何地方都没有副本。
不要再去 r3 的输出里找、也不要再跑"仅重打包"——`-package-r3d` 已实测报
`no trained checkpoint found for the private archive`，因为 r3 的输出目录里根本没有 `*.pt`。

**已有效的机制**（值得保留）：Kaggle 内核输出是持久的，后续内核可以 `kernel_sources`
挂载它；只要交付运行把文件写进 `/kaggle/working`，权重就能反复取，不需要重训。

**取回权重的唯一路径**：跑一次交付运行（约 90 分钟 T4），脚本现在会：
1. 打包后在日志和报告里打印 `[package] bytes by directory: {...}` 与 `private_bundle_breakdown`；
2. `shutil.copy2(private_zip, /kaggle/working)`，让 zip 成为持久内核输出；
3. 若 relay 把上传 session 送进内核（日志里 `upload_session_present: true`），再顺手传 Drive。

**顺手可做的验证**（可选，不改动正式产物）：当前 zip 的 `model/*.pt` 是 fp32（每个约 250 MB），
如果确认推理只用 CPU、可以转 fp16 存一份 `model_fp16/`，包体大约能减六成；
`model/*_scores.npz` 保留 fp32 的 OOF 分数，校准与操作点不受影响。

## 5. 发布动作清单（每次照做）

1. 生成发布包（§3），确认 `v2_1_release_summary.json` 的 `tier` 与 `release_blockers`。
2. commit + push 到当前分支；`git tag -a` 打标签，`gh release create --prerelease`。
3. 归档 zip 到 Drive，然后 **`make_private` + `list_permissions`** 复核只剩 owner。
4. 结果文档里必须显式写出 blocker，不得把探索性数字写成"验证过的性能"。
