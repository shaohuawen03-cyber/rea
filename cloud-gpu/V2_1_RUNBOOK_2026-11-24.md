## 4. 私有权重包：为什么 `.pt` 必须、又是怎么搬出去的

### 4.1 r3 的包为什么没了

r3 生成的 759,753,038 B 包只存在于容器的 `/tmp/v21-*`：那版脚本打包后只调上传，
**没有写进 `/kaggle/working`**，上传 session 又在训练启动前被 relay 消费。容器销毁即字节消失。
2026-11-25 两次重拉 r3 输出清单确认只有 `.log` × 2 + `progress.json` + `report.json`；
`-package-r3d` 报 `no trained checkpoint found for the private archive`。**没有可救的副本。**

### 4.2 三条约束决定了搬运方式

| 约束 | 后果 |
| --- | --- |
| relay 本地只拷 ≤2 MiB 的产物（`MAX_GIT_FILE_BYTES`），且跳过 `.pth/.safetensors/.onnx/.gguf` | 760 MB 的 zip **不会**自动进 `cloud-gpu/results` |
| 仓库是 **public** | 权重、正例序列、台账**绝不能**进 git，哪怕走 LFS |
| 沙箱出网白名单只有 github/pypi/npm | 本环境无法直连 HF Hub 或 Drive API |

所以搬运只走两条私密通道：**内核跑动里的上传**（`[package]` 后立即 PUT），以及
**跑完后从内核输出取回 + `stage_private_bundle.py` 转投 Drive**。

### 4.3 已落地的机制

1. `shutil.copy2(private_zip, /kaggle/working)` —— zip 成为持久内核输出；
2. `model_bundle_parts/part_NNN.bin` + `PARTS_MANIFEST.json` —— 1900 KiB 分卷，
   **每片都 < 2 MiB**，重组后 sha256 与整包一致（已用 6 MB 伪包端到端验证）；
   759,753,038 B 预计 **391 片**；
3. `cloud-gpu/scripts/stage_private_bundle.py` —— 只挑出 zip（不碰序列/台账），
   有 session URI 就直投 Drive，没有就留在磁盘等下一步；
4. 日志打印 `[package] bytes by directory: {...}` 与 `private_bundle_breakdown`，
   下次一眼看清 760 MB 花在哪。

### 4.4 尚未打通的一段（必须知道）

**分卷当前不会自动进仓库**：公网仓库 + 权重二进制 = 违反 v2 铁律。要用分卷这条兜底路径，
需要一个**私有**存放点，三选一：

| 方案 | 额外授权成本 | 说明 |
| --- | --- | --- |
| Drive 直传（首选） | 一次性的信封（`cloud-gpu/secrets/*.enc`） | 需在 relay 跑批前封一次新 session |
| 私有镜像仓库 `rea-private` | 新建仓库 + 推送权限 | 分卷天然适配 git 工作流 |
| Kaggle Dataset / Model | 需要 Kaggle token 带 create 权限 | 平台侧保存，可长期取回 |

## 5. 发布动作清单（每次照做）

1. 生成发布包（§3），确认 `v2_1_release_summary.json` 的 `tier` 与 `release_blockers`。
2. commit + push 到当前分支；`git tag -a` 打标签，`gh release create --prerelease`。
3. 归档 zip 到 Drive，然后 **`make_private` + `list_permissions`** 复核只剩 owner。
4. 结果文档里必须显式写出 blocker，不得把探索性数字写成"验证过的性能"。
