# positive_core_v2 冻结重训 Runbook（自动证据裁决版）

**当前状态：** 自动裁决策略已获用户授权（Arena 2026-11-12；见 `cloud-gpu/audits/2026-11-18-review-literature/auto_adjudication_policy_v2_1.0.md`），但**全量原始输入尚未完成受控下载/哈希，逐条证据账本尚未生成，strict v2 数据集尚未冻结，因此正式训练仍阻塞**。旧的 230 行人工抽样表不再要求逐条回填；它只保留作 QC 抽样对照，不替代 3,579 条全量裁决。

> 绝不把自动裁决伪装成 PI 人工签字；自动规则授权只批准了方法，不等于每条记录证据已验证或湿实验完成。

## 1. 自动证据规则（唯一正式口径）

规则版本：`auto_evidence_v2_1.0`。规则定义见 `cloud-gpu/audits/2026-11-18-review-literature/auto_adjudication_policy_v2_1.0.md`。

- `AUTO_CONFIRMED_ANTIBACTERIAL`：至少一条可追溯 DOI/PMID/PMCID 的全文实验结果，序列/衍生物确证对应，明确细菌目标、实验方法、阳性结果和原文位置。
- `AUTO_EXCLUDED_NONBACTERIAL`：可追溯全文仅支持非细菌 endpoint；只从抗菌任务排除，不等于实验阴性。
- `AUTO_SEQUENCE_MISMATCH`：序列、衍生物或源记录无法可靠映射。
- `AUTO_CONFLICT`：证据或身份存在未解冲突。
- `AUTO_UNRESOLVED_NO_EVIDENCE`：无足够证据；保持未决，不作负例。

不能凭论文标题、摘要 AMP 字样、来源数据库泛标签或模型预测确认抗菌阳性。全文不可达、sequence mapping 不明、experiment endpoint 不清均隔离。

## 2. 数据获取与隐私

1. Drive 中原始 positive FASTA、metadata、canonical sample、NOT_SIGNED literature pass 通过短时 `anyone-with-link` 只读权限供私有 Kaggle kernel 下载。
2. 权限仅在运行窗口打开；任务完成或失败即 `make_private`，随后 `list_permissions` 确认只剩 owner。不得把链接或原始序列写入 queue、GitHub、公开 Artifact 或公开 Release。
3. Kaggle `/tmp` 只读输入、计算 SHA-256/全量 ID 对账/证据抽取；临时原始下载在 kernel 结束前删除。
4. 返回 GitHub 的只允许脱敏 aggregate preflight JSON、普通日志和状态；正例 FASTA / 全量metadata /逐行阳性证据表留在私有 Drive 或受控私有存储。

## 3. 全量数据冻结门控

主候选全集目前项目账本规模为 3,579（2,895 targeted explicit + 666 target unknown + 18 generic-upgraded）；实际 FASTA 与 metadata 行数/ID闭合必须在 download job 中重新测量，不以旧数字代替。

先运行 `cloud-gpu/jobs/dualamp_v2_preflight_download.py`。只当其 `preflight_report.json.status == PREFLIGHT_OK_NOT_TRAINING`、metadata/FASTA ID 集完全相等，且 canonical/回填 ID 映射可解释时，才进入批量证据检索。

完整逐证据 ledger 使用 `cloud-gpu/audits/2026-11-18-review-literature/evidence_ledger_template.tsv`。候选可有多行文献记录；没有证据的候选也必须有一行明确 unresolved，不允许漏行。每条 evidence 保存 PMID/DOI/PMCID、source URL、fulltext/table location、序列 match、目标菌/菌株、assay、原始 MIC 字符串/单位、活动结果、Fulltext 状态、冲突、规则版本和时间戳。

使用严格冻结器：

```bash
python cloud-gpu/scripts/freeze_auto_evidence_v2.py freeze \
  --fasta positive_core_candidate_v1.fasta \
  --metadata positive_core_candidate_v1_metadata.tsv \
  --evidence evidence_ledger.tsv \
  --outdir positive_core_v2_auto \
  --rule-version auto_evidence_v2_1.0
```

门控必须同时满足：

- metadata 与 FASTA ID 集完全相同；每个 candidate 都有 evidence-ledger 行；无多余 ID；
- 只有满足全文实验、细菌 endpoint、序列 match、activity result 和原文定位的候选进 strict FASTA；
- 未决、非细菌、错配、冲突记录完整分流；样本/序列/来源映射可闭合；
- manifest 包含源文件与输出 SHA-256、条目数、唯一序列数、决策分类计数；
- 做 exact dedupe 后保留 `source_map_v2.tsv` 的一对多映射；训练之前另行验证 sequence homology/source grouped split，无 train/test 泄漏；
- 独立检查 negatives：未注释和无引用记录不当 experimental negative。weak negatives 单独标记并做敏感性分析。

任何一项失败：不得训练。230 行 sampled QC 的 5% `REJECT+CONFLICT` stratum heuristic 仅是警报，不得把未决计作 reject，也不应用它替代全量证据门控。

## 4. 正式训练（strict dataset 冻结后）

- 新任务 ID：`dualamp-real8-v2-<UTC-date>`；不得覆盖 real5/real6/real6b/real7。
- 输入为私有 Drive 中冻结的 `positive_core_v2.fasta`，queue 只携带 Drive ID 和 SHA-256；短时访问窗遵循开窗—派发—完成即撤权—权限复核。
- 模型/评估沿用 `cloud-gpu/jobs/dualamp_pilot.py --mode real --neg-mode standard` 路径，但必须确认使用的是 v2 FASTA hash 与冻结后的 split manifest；M1/M2 为主模型，M3 仅对照/消融。
- 5 seeds；Development OOF 确定阈值；分组独立 test；输出 AUROC/AUPRC/MCC/sensitivity/specificity、校准和置信区间，并完成 composition/scrambled challenge 与 real5/real6/real6b/real7 对照。不可把 pilot test 说成独立盲测，也不可把预测性能说成湿实验活性。
- 运行日志保存唯一 run ID、源数据 hash、代码 commit、环境版本、参数、split、阈值和模型权重 hash。

## 5. 归档与发布

- 权重、scaler 和配置包保存在**私有持久化位置**，用 SHA-256 manifest 验证；公开 Git 只保留代码、脱敏结果和 hashes，不存阳性原始数据或模型权重二进制。
- 只有 real8 实际训练、重复种子与完整评估均成功，才可打正式 v2 release。正式论文结果必须来自本次 v2 运行，不用 PILOT 数字替代。
- 如任何预设门控失败，应保留诊断产物并停在数据阶段；不得伪造训练完成或权重验证。
